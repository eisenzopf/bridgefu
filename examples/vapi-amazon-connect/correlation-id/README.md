# Pass a lookup token in SIP

Use the [six-step setup](../SETUP.md) to try both recipes in a disposable environment. For your own infrastructure, follow the [service-by-service walkthrough](../EXISTING-ENVIRONMENT.md) and select this directory's `settings.example.json`.

The default four application values are the same as the [header example](../sip-headers/README.md). The transfer Lambda stores them in DynamoDB with an explicit expiry and puts only an opaque token in the configured SIP header. By default that is `X-Correlation-Id`, mapped by Bridgefu to the customer attribute `handoff_id`. Both names and the TTL are configurable.

Bridgefu forwards the selected header into the contact's attributes. It does not generate this token or query DynamoDB. The entry flow invokes the lookup Lambda, which validates the Connect instance, retrieves the unexpired item, and returns the configured field names. The flow sets `$.Attributes.<configured-name>` before transferring to your target flow.

The status attribute defaults to `handoff_status`. It is `found` when context resolves and `unavailable` for a missing/expired token. Lookup failures still route the caller to your target flow; use that flow to choose how agents handle missing context. Do not mistake successful audio routing for successful context retrieval. Expiry is checked by Lambda because DynamoDB TTL deletion is asynchronous.

The token is generated by the server, bound to one call/tool invocation, and reused for a consistent retry of that invocation. It contains no customer data. An ambiguous transfer timeout is not automatically retried. Context is not consumed on lookup, so retries within the TTL work. This is an example retention policy, not a mandatory Bridgefu behavior.

Every application field, source, SIP/token name, Connect attribute, status name, and expiry is customer configurable. The four field headers in settings are unused in this mode; only the correlation header crosses SIP. The flat lookup result is deliberately bounded for Connect's Lambda limit.

Verify all configured attributes and `found`, then test missing and expired tokens. See [E2E instructions and results](../tests/E2E.md).
